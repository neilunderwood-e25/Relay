Run Relay from source

Relay is a local Electron app you build yourself. This page covers prerequisites, the dev loop, the verification gates, the workspace it creates, and the release work that is deliberately still open.

Getting started

Prerequisites

  • Node.js 22 or newer
  • npm
  • Git
  • Claude Code and/or Codex CLI on PATH, already installed and authenticated

Relay drives whichever provider CLIs it can find. One is enough to start; both are needed for the real-CLI tests and for mixed Claude + Codex runs.

Install and start

bash 
npm install
npm run dev

npm install also runs electron-builder install-app-deps, which rebuilds the native better-sqlite3 and node-pty modules for your Electron version. npm run dev starts the app through electron-vite.

Startup wizard

On first launch no project is selected. The startup dialog asks for two paths:

  • Harness Home — where Relay keeps relay.db and its coordination state. It is created if needed and must be readable and writable.
  • Git project — the single coding project. It must be a Git worktree on a checked-out local branch.

The two folders cannot contain one another, selected paths are canonicalized, and Michael's provider and model are re-verified at every startup. Missing CLIs and invalid paths produce visible, actionable errors instead of a broken session.

Use a disposable project first. Relay creates branches and worktrees inside the project you select. Start on a clean local branch with at least one commit.

Verification

The everyday gates before you trust a change:

bash 
npm run typecheck
npm test
npm run build

All scripts

Command What it does
npm run dev Start the app in development mode via electron-vite.
npm run build Production main, preload, and renderer build. The final verification gate for renderer work.
npm run typecheck TypeScript, no emit, across both the Node and web projects.
npm test The full Vitest suite, including design-system invariants and release checks.
npm run test:cli Opt-in real-CLI worktree smoke test. Launches your installed, authenticated Claude Code and Codex CLI clients in disposable repositories.
npm run test:e2e The repeatable local gate: typecheck, full suite, production build, then both real-CLI smoke tests.
npm run pack:mac:unsigned Build an unsigned macOS .app bundle in dist/.

npm run test:cli is opt-in on purpose: it invokes real CLI binaries. It uses disposable repositories and isolated worktrees, confirms read-only planning does not change the project, confirms worker changes stay inside their worktree, and creates no commits.

Packaged-app acceptance stays a separate human-style pass, because it exercises native dialogs, window state, and visual terminal behavior. That script lives in FULL_E2E_CHECKLIST.md, and the gate list plus deferred distribution work lives in RELEASE_CHECKLIST.md.

Your first run

  1. Write one objective and choose a run mode — Build, Split, or Audit. Split accepts newline or semicolon-separated instructions as parallel workstreams.
  2. Pick your crew. Load a saved team template, or select individual saved agent profiles. Set agent concurrency.
  3. Let Michael plan. The run opens in a persisted planning state; planning is read-only and cannot modify the repository. Michael returns a one-to-four task plan; a deterministic fallback is used if the model output is unusable.
  4. Watch the workers. Each task gets a relay/orchestrator-* branch and a managed worktree. Open Console for live Claude and Codex output. Your main checkout stays unchanged.
  5. Handle blockers. A worker that emits RELAY_BLOCKER becomes a blocked task plus a durable message for Michael. Failed, blocked, or stopped runs can be re-planned with the prior evidence attached.
  6. Review every task. Inspect the bounded per-file diff, then accept or reject. Integration stays disabled until all tasks are reviewed.
  7. Integrate. Accepted tasks are squashed onto the checked-out base branch in task order. Integration refuses a dirty checkout or the wrong branch; conflicts are reported by file and aborted cleanly.
  8. Verify, then clean up. Final verification runs through an available CLI in read-only mode and its report is retained. Cleanup only removes completed managed worktrees after verification — task branches remain for recovery.

Everything above is persisted. If the app restarts mid-run, interrupted work is surfaced as blocked, hive projections are repaired, pending controls are replayed once, and no branch or worktree is deleted.

Workspace layout

Relay stores its database and coordination state in the Harness Home you selected. The task ledger and message stream are plain files, readable without the UI. 

Harness Home/
  relay.db
  hive/
    PROTOCOL.md
    registry.json
    board.md
    tasks.json
    log.jsonl
    messages.jsonl
    control/
      inbox/
      outbox/.processing/
      outbox/.done/
      results/
      actions/
    agents/orchestrator/
      identity.md
      memory.md
      context.md
      history.jsonl
      cursor.json
      inbox/.done/
      outbox/.sent/

Michael's identity is refreshed by the harness while memory.md is never overwritten. Renaming the orchestrator updates its identity and registry without moving its stable folder. Managed worktrees are not stored here — they live inside the project under .relay/worktrees/.

Architecture

The renderer has no direct Node access. Filesystem, database, Git, PTY, and provider operations stay in the Electron main process and are exposed through narrow typed IPC contracts.

  ├── provider adapter registry + discovery
  ├── SQLite persistence
  ├── agent profile + team template registry
  ├── persistent orchestrator hive workspace
  ├── durable bidirectional control protocol

macOS packaging

Build an unsigned application bundle, or unsigned DMG and ZIP artifacts:

bash 
npm run pack:mac:unsigned
npm run dist:mac:unsigned

Expected Apple Silicon artifacts:

dist/mac-arm64/Relay.app
dist/Relay-0.1.0-arm64.dmg
dist/Relay-0.1.0-arm64.zip

The package uses ASAR and carries only production dependencies plus the Darwin native modules the bundle needs. The bundle icon source is build/relay-app-icon.svg; development mode uses the PNG for the live Dock icon.

The macOS application does not need Accessibility or Screen Recording permission. Those are only required by external UI-automation tools used to inspect the app.

Release boundary

There is no downloadable Relay release. macOS signing, notarization, hardened runtime, and public distribution are intentionally deferred. Version 0.1.0 is validated as a local, unsigned build that you compile from source yourself.

An unsigned bundle has no signing identity, hardened runtime, notarization ticket, or Gatekeeper assessment. Another Mac may warn about it or refuse to open it until signed release work is done.

Deferred distribution work

  • Apple Developer ID certificate and secure CI secret handling
  • Hardened runtime and entitlements
  • Notarization and stapling
  • Gatekeeper verification on a clean macOS machine
  • Update channel, release publishing, and rollback policy

What is validated

  • Onboarding persistence, permission policy, and package configuration checks in the automated suite
  • Watchdogs, bounded buffers, workspace validation, and both provider adapters
  • The repeatable local npm run test:e2e gate
  • A human-style packaged-app acceptance pass covering startup through cleanup, restart recovery, and traversal rejection

The authoritative lists are RELEASE_CHECKLIST.md and FULL_E2E_CHECKLIST.md in the repository.
