Overview

Introducing Relay: many coding agents, one orchestrator

29 August 2026 Milestones 01–17

Relay is a local-first desktop multi-agent coding harness. You give it an objective; Michael — the default orchestrator — plans bounded work for Claude Code and Codex CLI workers that run in isolated Git worktrees on a single coding project.

A harness, not a service

Relay is an Electron desktop app you build and run yourself. There is no Relay account, no Relay backend, and no telemetry endpoint in the app. It drives the provider CLI clients you already installed and authenticated, against a Git repository you already have on disk, and provider authentication stays wherever Claude Code and Codex CLI already keep it.

That shapes the prerequisites: Node.js 22 or newer, npm, Git, and Claude Code and/or Codex CLI on your PATH. One provider is enough to start. Both are needed for the real-CLI tests and for mixed Claude + Codex runs.

What a run looks like

You write one objective and pick a run mode. Build mode assigns an implementation owner and an independent reviewer. Split mode turns newline- or semicolon-separated instructions into parallel workstreams. Audit mode asks each worker for an independent, evidence-backed investigation.

The objective is persisted before delivery, then handed to Michael's shared session. Michael inspects it in a read-only planning mode and returns a validated plan of one to four tasks, each with an explicit role, assignment, and expected deliverable. Every task then receives a dedicated relay/orchestrator-* branch and a managed worktree, so Claude and Codex can work concurrently without ever touching your main checkout.

When the workers finish you inspect a bounded per-file diff, accept or reject every task, and only then does Relay squash accepted work onto your checked-out base branch — followed by read-only verification through an available CLI, and cleanup of worktrees whose branches are left intact for recovery.

The parts that make it reviewable

  • Provider adapter registry. One contract covers discovery, worker launch, and read-only verification across Claude Code and Codex.
  • SQLite persistence. Runs, tasks, reviews, verification reports, and an append-only event ledger survive restarts; interrupted work is surfaced as blocked.
  • Durable control protocol. Bidirectional inbox/outbox files with an allowlisted action set, durable receipts, and replay after a crash.
  • Structured logs. Run, Git, terminal, and system events are filterable in Activity and readable outside the UI.
  • node-pty supervisor. Real interactive terminals with bounded replay buffers, watchdog timeouts, and forced shutdown on exit.

The Electron main process owns every privileged operation. The React renderer has no direct Node access and reaches the filesystem, database, Git, PTYs, and provider CLIs only through narrow typed IPC contracts.

Where the boundary sits

Relay is developed and verified as a local build. macOS signing, notarization, hardened runtime, and public distribution are intentionally deferred, so there is no downloadable release. You can produce an unsigned macOS bundle or unsigned DMG and ZIP artifacts locally, but they carry no signing identity, notarization ticket, or Gatekeeper assessment — another Mac may warn or refuse to open them until that work is done.

The docs cover the dev loop, the verification gates, and the workspace Relay creates. The features page goes subsystem by subsystem.
