Isolation

Worktree isolation, and what it refuses to do

31 August 2026 Worktree & integration safety

Running several coding agents at once is only safe if none of them can surprise you in your own checkout. Relay's answer is one managed Git worktree per task, plus a set of removals the manager deliberately refuses.

One worktree per task

Every task in a run receives a dedicated relay/orchestrator-* branch and its own managed worktree. Managed worktrees live inside the project under .relay/worktrees/, matching the project-local workflow Claude Code already uses. Claude runs in non-interactive edit-accepting mode and Codex runs in a workspace-write sandbox with approvals disabled — both inside their isolated checkout, never in yours.

Relay adds /.relay/worktrees/ to the repository's local .git/info/exclude and does not modify your tracked .gitignore. Your committed Git configuration stays yours.

Validated before Git sees it

Worktree and branch names are validated before they reach Git, so a name such as ../escape is rejected up front rather than being resolved by the filesystem. Relay also refuses managed worktree storage that resolves outside the selected project, and refuses symlinked Hive control directories.

Relay's own Git commands run without a shell, using argument arrays rather than interpolated strings. They disable repository hooks, disable terminal prompts, inherit only the environment a local Git operation needs, and have bounded output and execution time.

The refusals are the feature

  • Removal refuses dirty worktrees and branches with commits ahead of their base.
  • A worktree cannot be removed while a live terminal is using it.
  • Missing worktrees stay visible and can be forgotten without touching repository content.
  • Removing a worktree leaves its Git branch intact for recovery.
  • Legacy worktrees under a previous Harness Home remain discoverable and removable.

Worker terminals may start only in the selected checkout or a live Git-registered worktree, and renderer requests cannot choose an arbitrary terminal directory, assume an internal terminal role, or inject provider CLI arguments. Every denied boundary request is recorded as an app.safety.denied system event, so refusals are auditable rather than invisible.

Nothing merges until you say so

Completed worker results expose a bounded per-file diff without changing Git state. Every task must be explicitly accepted or rejected before integration can begin. Accepted tasks are then squashed and applied to the checked-out base branch in task order — and integration refuses a dirty project checkout or the wrong checked-out branch outright. Conflicts are reported by file and aborted without leaving the project in a conflicted state.

Final verification runs through an available CLI in read-only mode and its report is retained. Cleanup removes completed managed worktrees only after verification, and task branches remain for recovery. If the app is interrupted, recovery marks the interrupted work as blocked, repairs hive projections, and reports missing worktrees without deleting branches or files.

How it is checked

The packaged acceptance pass exercises this end to end: a Split-mode Claude + Codex run, worktrees created under <project>/.relay/worktrees/ on relay/* branches, a main checkout that stays unchanged until integration, one Relay commit per accepted task, a required passing verification report before cleanup is enabled, and worktree directories removed while their branches remain available. It also requires rejecting a traversal-style worktree name and refusing cleanup of dirty, ahead, or terminal-owned worktrees.
