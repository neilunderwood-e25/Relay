How it works

Objective in, reviewable commits out

Four steps, all persisted. Nothing touches your checked-out branch until you accept the work yourself.

1

Objective in

You write one objective and pick a run mode — build, split, or audit. It is persisted before delivery, then handed to Michael's shared session.

2

Michael plans

Michael inspects the objective in read-only plan mode and returns a validated one-to-four task plan with roles, deliverables, and provider assignments. Bad output falls back to a deterministic plan.

3

Workers run isolated

Each task gets its own relay/orchestrator-* branch and managed worktree under .relay/worktrees/. Claude and Codex work concurrently, never in your main checkout.

4

Review & integrate

Inspect a bounded per-file diff, accept or reject every task, then squash accepted work onto your base branch — followed by verification and cleanup.

Architecture

What's actually in the harness

The Electron main process owns every privileged operation. The React renderer has no direct Node access and reaches the system only through narrow typed IPC contracts.

Provider adapter registry

One contract for discovery, worker launch, and read-only verification across Claude Code and Codex.

SQLite persistence

Runs, tasks, reviews, verification reports, and an append-only event ledger survive restarts.

Agent profiles & team templates

Reusable named agents with provider, model, and instructions; templates save an objective, mode, and roster.

Durable control protocol

Bidirectional inbox/outbox files with allowlisted actions, durable receipts, and replay after a crash.

Git worktree manager

Validated names, project-local managed worktrees, and removal that refuses dirty or ahead branches.

Planner + concurrent scheduler

Model-produced bounded plans, deterministic fallback, bounded concurrency, stop, and per-task retry.

Hive messages & blocker routing

A worker's RELAY_BLOCKER report becomes a blocked task plus a durable message in Michael's inbox.

Structured logs

Run, Git, terminal, and system events are filterable in Activity and readable outside the UI.

node-pty supervisor

Real interactive terminals with bounded replay buffers, watchdog timeouts, and forced shutdown.

Local-first

Your machine, your keys

Relay is a desktop harness, not a hosted service. It drives the CLI clients you already installed and authenticated, against a Git project you already have on disk.

There is no Relay account, no Relay backend, and no telemetry endpoint in the app. Provider authentication stays wherever Claude Code and Codex CLI already keep it.

  • Nothing leaves your box except the requests your own provider CLIs make.
  • State lives in a folder you pick. A Harness Home holds relay.db and the hive workspace.
  • Scoped by project. The main process authorizes every repository, worktree, run, task, and terminal request against the selected project.
  • Bounded environment. CLI child processes get a small allowlist for auth and terminal basics instead of every host secret.
  • Your Git stays yours. Relay excludes its worktrees via .git/info/exclude and never edits your tracked .gitignore.
  • Denials are auditable. Every refused boundary request is recorded as an app.safety.denied event.

Build it and run it locally

Relay is developed and verified as a local build. macOS signing, notarization, and public distribution are intentionally deferred — there is no downloadable release.
